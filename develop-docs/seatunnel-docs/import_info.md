我仔细阅读了seatunnel官方的一些文档结合我们的实际场景，我得到了以下信息：

1. 我们的数据迁移场景的来源只有 “Oracle， PG”

2. 我们的数据迁移目标数据库只有 "PG， Doris，Oracle(比较少，大部分是前两者)"

3. 关于“source”的文档，我仔细阅读了区别发现不管是Oracle还是PG都大同小异，两者其实都是jdbc而已。

4. 对于sink部分，发现不管是Oracle还是PG都大同小异，也都是jdbc，两者的配置文件只有driver和url部分是不同的；倒是doris和他们两者都不同。

5. 由于Transform的存在，我们的表单还需要支持多 “source”，多“sink”

6. 对于数据库连接信息，不能让用户填写，而是使用ds自带的数据源功能，这部分是持久化在数据库中的，不管是在"source"还是“sink”，用户选择之后自动映射成json字符串（而且这部分敏感数据在右侧画布展示的时候应该是加密的）。

7. 对于source部分我需要考虑哪些是最基本的用户必选的选项，或者必填的选项，以及保留“高级选项”，比如那些并行部分的参数

8. 对于sink部分是一样的，我需要考虑那些是必填的用户选项，以及哪些是高级功能
